# EmployeeAudit

Плагин [Vencord](https://github.com/Vendicated/Vencord) для фракции «Больница»
на GTA 5 RP проекте **Russia Online**.

По клику в контекстном меню сообщения-отчёта на повышение собирает кадровый
аудит и кладёт его в буфер обмена (или сразу в поле ввода) — текстом или
вызовом бота.

## Что делает

Правый клик по сообщению-отчёту даёт два пункта; лишний отключается в настройках.

**Copy Employee Audit** — аудит текстом, как его писали руками до бота:

```
Повышение
Повышает: <@100000000000000000> Виктор Громов | 500
Повышен(а): <@100000000000000001> Артур Белов | 10001
Прежний ранг: 5
Новый ранг: 6
Причина повышения: https://discord.com/channels/…/…/…
```

**Copy Promotion Command** — вызов бота, который теперь заполняет аудит сам:

```
/повышение пользователь:<@100000000000000001> был:5 стал:6 причина:https://discord.com/channels/…/…/…
```

Аргументы именованные, потому что вставленный текст Discord в аргументы команды
не разбирает: сначала выбирается сама команда, а имена нужны, чтобы значения
встали по своим местам. Повышаемый идёт упоминанием — из него аргумент
«пользователь» заполняется сразу, тогда как текстовый `@хендл` остался бы
текстом. Повышающий в команде не указывается: бот берёт его из того, кто её
вызвал, поэтому имя и статик для этого пункта заполнять не нужно.

Команду можно собрать и из короткой заявки, написанной руками, — бот для неё
не нужен:

```
<@921022797029994507>
3-4
https://discord.com/channels/…/…/…
@Роль @Роль
```

Из неё берутся повышаемый (первое упоминание), номера рангов и ссылка —
она и идёт в «причину». Пинги ролей игнорируются. Имени и статика в заявке нет,
поэтому пункт с текстовым аудитом на ней не показывается.

**Carry Out Promotion** — повышение целиком: меняет роли, правит ник, ставит
галочку на сообщение-отчёт и кладёт в буфер обмена команду `/повышение`.
Остаётся выбрать команду в канале аудита и вставить аргументы.

Отправить slash-команду плагин не может — она ушла бы обычным сообщением,
поэтому последний шаг остаётся ручным. Публикация **текстового** аудита тоже
есть отдельным шагом, но выключена по умолчанию: с сентября 2026 аудит
заполняет бот, а текстом его пишут только там, где бота нет. Пункт **выключен по умолчанию** — в отличие от остальных, он
не кладёт текст в буфер, а совершает необратимые действия, поэтому включается
вручную.

Перед выполнением показывается окно со сводкой: кого повышаем, какие роли
выдаём и снимаем, каким станет ник, в какой канал уйдёт аудит. Пока в нём не
нажать «Провести», не происходит ничего.

Роли и отдел в нике меняются **только на входе в средний состав** (3 → 4,
роль «Интерн» → «Отдел СМП», ник `Интерн | Юрий Белый | 87052` →
`СМП | Юрий Белый | 87052`). Повышение внутри состава их не трогает: аудит и
галочка при этом всё равно делаются. Ник правится заменой первого сегмента, а
не сборкой заново по отчёту, — иначе сокращённые до буквы имена (`Е. Куртасов`)
восстанавливались бы в полные и упирались в лимит Discord в 32 символа.

Шаги выполняются по порядку — роли, ник, аудит, галочка — и останавливаются на
первой же ошибке. Галочка идёт последней и означает «сообщение отработано
целиком»: если что-то не прошло, её не будет, и это видно в списке сообщений.
Каждый шаг можно выключить отдельной настройкой. До окна подтверждения
проверяются права («Управлять ролями», «Управлять никнеймами»), иерархия ролей
(роль не ниже вашей высшей Discord тронуть не даст) и то, что роли из настроек
на сервере вообще есть, — чтобы отказ не приходил уже посреди выполнения.

Пункты меню появляются только на отчётах и заявках и только в каналах из
настройки (по умолчанию — канал отчётов бота и канал заявок).

Интерфейс плагина двуязычный: настройка **Interface language** — `Auto`
(по языку Discord), `English`, `Русский`. Русским в обоих случаях остаётся то,
что уходит в игру: сам текст аудита и названия полей отчёта.

## Установка коллегам — готовая сборка

Если собирать нечем и не хочется, возьмите архив из
[релизов](https://github.com/JellyColonel/EmployeeAudit/releases): внутри
собранный Vencord с плагином и `install.bat`, который делает резервную копию и
подкладывает файлы. Нужен уже установленный Vencord — плагин заменяет его
сборку, а не ставит с нуля. Обновление потом — `update.bat`, он скачивает
последний релиз сам. Ни git, ни Node для этого не нужны.

Оговорка: в такой сборке встроенный апдейтер Vencord отключён, обновляться надо
через `update.bat`.

## Установка из исходников

Плагин из `userplugins` работает только в Vencord, собранном из исходников:

```bash
git clone https://github.com/Vendicated/Vencord
cd Vencord && pnpm i

git clone https://github.com/JellyColonel/EmployeeAudit src/userplugins/EmployeeAudit

pnpm build && pnpm inject
```

Симлинком плагин подключить нельзя: esbuild резолвит реальный путь, файлы
оказываются вне дерева Vencord и алиасы `@utils/*` не разрешаются. Нужен клон
или копия внутри `src/userplugins/`.

Затем включить плагин в настройках Vencord. Для текстового аудита **обязательно
заполнить своё имя и Static ID** — без них он не соберётся; Discord ID можно
оставить пустым, тогда подставится текущий аккаунт. Команде бота эти поля не
нужны, она работает и с пустыми настройками.

Для разработки: `pnpm watch`, перезагрузка Discord по Ctrl+R.

## Выпуск релиза

```bash
scripts/make-release.sh          # тег по дате
scripts/make-release.sh v2026.09.05
```

Скрипт собирает Vencord с плагином, пакует `dist` вместе с установщиками и
публикует релиз через `gh`.

## Разработка в WSL при Discord на Windows

Если Vencord уже установлен на Windows официальным установщиком, Node на Windows
не нужен: установщик подменил `app.asar` заглушкой, которая грузит
`%APPDATA%\Vencord\dist`. Папка виндовая, но из WSL она доступна на запись через
`/mnt/c`, поэтому достаточно собрать в WSL и подложить туда результат:

```bash
scripts/deploy-to-windows.sh
```

Скрипт собирает Vencord, закрывает Discord, делает резервную копию `dist`,
копирует свежие файлы и запускает Discord обратно. Перезапуск обязателен:
`patcher.js` читается один раз при старте, и Ctrl+R новую сборку не подхватит.

Discord закрывается только после успешной сборки — падение сборки не выбьет
работающий клиент. Открывается обратно лишь тот, который скрипт сам закрыл.
`RESTART_DISCORD=0 scripts/deploy-to-windows.sh` оставляет прежнее поведение:
только скопировать, а закрывать и запускать вручную.

## Настройки

| Настройка | Назначение |
|---|---|
| Имя и фамилия, статик, Discord ID | строка «Повышает» |
| Язык интерфейса | Auto (как в Discord) / English / Русский |
| Каналы | ID каналов через запятую, где показывать пункты меню. Пусто — во всех |
| Что делать по клику | копировать / вставить в поле ввода / и то и другое |
| Показывать пункт «аудит» / «команда» / «повышение» | каждый пункт меню включается отдельно; «повышение» по умолчанию выключено |
| Шаги повышения | роли, ник, аудит, галочка, команда в буфер — каждый включается отдельно; текстовый аудит по умолчанию выключен |
| Граница среднего состава | ранг, при переходе через который меняются роли и отдел в нике (по умолчанию 4) |
| Роли выдать / снять | ID ролей через запятую, меняются только на этой границе |
| Отдел | первый сегмент ника: `Отдел \| Имя Фамилия \| Static ID` |
| Канал аудита | куда публикуется текст аудита |
| Эмодзи отметки | чем помечается обработанное сообщение (серверная — `имя:id`) |
| Шаблон аудита | текст с плейсхолдерами `{targetName}`, `{oldRank}`, `{reportLink}` и др. |
| Шаблон команды | те же плейсхолдеры; аргумент «пользователь» заполняется из `<@{targetId}>` |
