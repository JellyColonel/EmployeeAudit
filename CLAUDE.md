# EmployeeAudit — плагин Vencord

## Контекст

**Игровой проект:** Russia Online / Россия Онлайн — GTA 5 RP сервер от создателей Majestic.
Открылся 20 августа 2025 г., поэтому серверной автоматизации (ботов) для кадровых
процессов ещё нет — всё делается вручную.

**Пользователь:** Инструктор отдела «Скорая Медицинская Помощь» во фракции «Больница».

**Обязанности, к которым относится плагин:**
- проверка отчётов на повышение сотрудников среднего состава;
- собственно повышение;
- отписывание **кадрового аудита** — один из шагов повышения.

**Проблема:** кадровый аудит пишется руками по шаблону, данные для него берутся
из embed-сообщения с отчётом на повышение. Это рутина, которую обычно закрывают
ботом, но на этом проекте бота пока нет.

## Задача плагина

Прочитать сообщение-отчёт на повышение (Discord embed) → собрать по шаблону текст
кадрового аудита → положить его в буфер обмена по клику пункта в контекстном меню
сообщения.

## Технические решения

- Патчи Webpack, скорее всего, **не нужны**: хватит `@api/ContextMenu`
  (`addContextMenuPatch("message", ...)`) + данные сообщения из аргументов меню /
  `MessageStore`.
- Копирование — `copyWithToast` из `@utils/misc` (копирует и показывает тост).
- Настройки — `definePluginSettings` из `@api/Settings`: шаблон текста аудита,
  личные данные проверяющего, ограничение по каналам/фракции.
- Расположение: `src/userplugins/EmployeeAudit/` внутри собранного из исходников
  Vencord (готовая сборка userplugins не поддерживает).

## Окружение: WSL + Windows

Разработка идёт в WSL, а Discord с Vencord стоит на Windows. Проверено 01.09.2026:

| Что | Состояние |
|---|---|
| WSL-интероп (`.exe` из WSL) | работает |
| Node / pnpm **на Windows** | **не установлены** (есть только git и winget) |
| Node 24 + corepack **в WSL** | есть |
| Discord | `C:\Users\Valeriu\AppData\Local\Discord\app-1.0.9255`, stable |
| Vencord | уже установлен официальным установщиком |
| Запись в `%APPDATA%\Vencord` из WSL через `/mnt/c` | доступна (проверено) |

Ключевой факт: установщик Vencord подменил `app.asar` крошечной заглушкой

```js
require("C:\Users\Valeriu\AppData\Roaming\Vencord\dist\patcher.js")
```

то есть Discord грузит **строго эту папку**. Путь тут обычный виндовый, никакого
отношения к WSL он не имеет — важно другое: из WSL этот путь доступен **на запись**
через монтирование диска (`/mnt/c/Users/Valeriu/AppData/Roaming/Vencord/dist`),
что проверено записью тестового файла.

Отсюда следует, что **Node на Windows не нужен и `pnpm inject` запускать не надо**:
инжект уже сделан установщиком, а собранный в WSL `dist` можно положить в эту папку
с той стороны, где Node есть.

## Сборка и разработка

Vencord склонирован в `~/projects/Vencord`, плагин — в его `src/userplugins/`.
pnpm вызывается через corepack (`corepack pnpm …`), глобально он не установлен.

```bash
git clone https://github.com/Vendicated/Vencord ~/projects/Vencord
cd ~/projects/Vencord && corepack pnpm i
git clone https://github.com/JellyColonel/EmployeeAudit src/userplugins/EmployeeAudit

corepack pnpm build      # сборка
corepack pnpm testTsc    # проверка типов — ловит то, что сборка пропускает
corepack pnpm lint       # eslint Vencord, требует SPDX-заголовки в каждом файле
```

**Симлинк вместо клона не работает.** esbuild резолвит реальный путь файла, тот
оказывается вне дерева Vencord, и алиасы `@utils/*`, `@api/*`, `@webpack/common`
перестают разрешаться — сборка падает с `Could not resolve`. Нужен именно клон
или копия внутри `src/userplugins/`.

Доставка на Windows — `scripts/deploy-to-windows.sh`: собирает, делает резервную
копию `%APPDATA%\Vencord\dist` и подкладывает туда свежие
`patcher.js`, `preload.js`, `renderer.js`, `renderer.css` с картами.
`vencordDesktop*` не копируются — это файлы Vesktop. `package.json` в целевой
папке не трогается, его кладёт установщик.

После копирования Discord нужно **полностью закрыть** (трей → Quit) и запустить
заново; Ctrl+R не подхватит новый `patcher.js`.

### Что происходит с апдейтером Vencord после подмены

Проверено по исходникам 01.09.2026.

`pnpm build` без `--standalone` даёт не-standalone сборку, а Vencord по этому флагу
выбирает апдейтер: `require(IS_STANDALONE ? "./http" : "./git")` в
`src/main/updater/index.ts`. Значит после подмены работает **git-апдейтер**, а не
http-шный, который клал установщик.

Git-апдейтер выполняет команды с `cwd = join(__dirname, "..")`. `patcher.js` лежит
в `%APPDATA%\Vencord\dist`, то есть cwd — это `%APPDATA%\Vencord`, а git-репозитория
там нет. `git remote get-url origin` падает, ошибка доходит до `catch` в
`runUpdateCheck()` и гасится записью в консоль. Отсюда два следствия:

- **плашка «A Vencord update is available» больше не появляется**, и вкладка
  Updater в настройках показывает ошибку;
- **автообновление не сработает**, хотя `autoUpdate` включён по умолчанию. То есть
  риска, что официальный апдейтер молча перезапишет нашу сборку, нет.

Обновление Vencord теперь ручное, источник правды — клон в WSL:

```bash
cd ~/projects/Vencord && git pull && corepack pnpm i
cd ~/projects/VencordPlugins/EmployeeAudit && ./scripts/deploy-to-windows.sh
```

Перезапуск официального установщика Vencord вернёт стандартную сборку вместе с
апдейтером — и уберёт плагин до следующего прогона скрипта.

## Спецификация

### Вход: сообщение-отчёт

- Автор: бот **«Ева Повышаловна»**, id `1542575130168004712`.
- `embed.rawTitle === "Отчет на повышение"`, `embed.type === "rich"`.
- `message.content` = `<@&1541779227018526741> | <@USER_ID>` — роль проверяющих плюс
  **упоминание повышаемого**. Discord ID берём из последнего упоминания пользователя.
- Обязательные поля embed (искать по `rawName`, **не по индексу** — набор полей плавает):

| `rawName` | Пример `rawValue` | Идёт в аудит |
|---|---|---|
| `Имя Фамилия \| Static ID` | `Евгений Курчатов \| 45642` | да |
| `С какого на какой ранг повышаетесь?` | `Ординатор [5] → Старший ординатор [6]` | да (только числа) |
| `Дата последнего повышения` | `30.08.2026` | нет |
| `Общее количество баллов…` | `**301**` | нет |

- Плавающие поля (в аудит не идут, набор различается от отчёта к отчёту):
  «Оказание ПМП днём/ночью», «Таблетки в ГКБ им. Склифосовского», «Вакцины»,
  «Заполнение кадрового аудита», «Проверка отчета на повышение», «Остальное»,
  «Мероприятия».
- Известные вариации, которые парсер обязан пережить:
  - имя поля баллов: `Общее количество баллов`, `… (Нужно 300)`, `… (Нужно 400)`;
  - значение баллов с хвостом: `**410**, без учёта мероприятий`;
  - многострочное значение (`Остальное`: `Поставка +25Б\nhttps://…`);
  - ранг из двух слов с точками: `Зам. зав. отделением [10]`;
  - стрелка — символ `→` (U+2192).

### Выход: текст кадрового аудита

```
Повышение
Повышает: <@{promoterId}> {promoterName} | {promoterStatic}
Повышен(а): <@{targetId}> {targetName} | {targetStatic}
Прежний ранг: {oldRank}
Новый ранг: {newRank}
Причина повышения: {reportLink}
```

### Маппинг полей

| Строка аудита | Источник |
|---|---|
| `Повышает` | настройки плагина (сам пользователь) |
| `Повышен(а)` — `<@id>` | последнее упоминание пользователя в `message.content` |
| `Повышен(а)` — имя и статик | поле `Имя Фамилия \| Static ID` |
| `Прежний ранг` | первое число в скобках поля ранга |
| `Новый ранг` | второе число в скобках поля ранга |
| `Причина повышения` | `https://discord.com/channels/{guildId}/{channelId}/{messageId}` сообщения-отчёта |

Таблица званий **не нужна**: оба ранга и их номера уже есть в самом поле отчёта.

### Ранги СМП (средний состав)

| № | Название | № | Название |
|---|---|---|---|
| 4 | Фельдшер | 8 | Терапевт |
| 5 | Ординатор | 9 | Хирург |
| 6 | Старший ординатор | 10 | Зам. зав. отделением |
| 7 | Психиатр | 11 | Заведующий отделением |

Таблица нужна **только для проверки** (`ranks.ts`): ранги для аудита берутся из
самого отчёта. Несовпадение названия с номером или повышение не на один ранг
дают предупреждение, но копирование не блокируют.

### Тестовые данные

- `samples/reports/*.json` — четыре реальных отчёта, покрывают вариации выше.
- `samples/audits.txt` — эталонные аудиты, написанные вручную.
- Пара `01-ordinator-to-senior.json` → первый аудит в `audits.txt` — сквозной тест
  (совпадают и Discord ID, и имя, и статик, и ранги).

## Рабочий процесс

Изменения идут **через pull request'ы**: ветка от `main` → коммит → `gh pr create`.
Напрямую в `main` не пушим.

## Проверенные API Vencord

Сверено с веткой `main` репозитория Vendicated/Vencord (сентябрь 2026):

- `copyWithToast(text, toastMessage?)` — в **`@utils/discord`**, не в `@utils/misc`.
- `insertTextIntoChatInputBox(text)` — там же.
- Контекстное меню — свойство `contextMenus: { "message": patch }` в `definePlugin`,
  а не ручные `addContextMenuPatch`/`removeContextMenuPatch` в `start`/`stop`.
- `NavContextMenuPatchCallback`, `findGroupChildrenByChildId` — `@api/ContextMenu`.
  Якорь для вставки пункта в меню сообщения — id `copy-text`.
- `Menu`, `Toasts`, `UserStore`, `ChannelStore` — `@webpack/common`.
- Тип `Message` — `@vencord/discord-types`.
- `OptionType.STRING` поддерживает `multiline: true` (textarea для шаблона).

## Тесты

Чистая логика (`parser.ts`, `ranks.ts`, `template.ts`) не зависит от Vencord и
гоняется прямо здесь:

```bash
node --import ./test/hooks.mjs --test test/parser.test.ts
```

`test/hooks.mjs` дорезолвивает импорты без расширений — Vencord собирается
esbuild'ом и пишет их как `./parser`, а Node так не умеет.

## Структура

Корень репозитория **и есть** папка плагина: её можно симлинкнуть в
`Vencord/src/userplugins/EmployeeAudit`. Файлы вне `index.tsx` и его импортов
в сборку не попадают.

| Файл | Назначение |
|---|---|
| `index.tsx` | пункт контекстного меню, сборка и выдача аудита |
| `settings.ts` | настройки плагина |
| `constants.ts` | канал отчётов, заголовок embed'а, регулярки имён полей |
| `channels.ts` | разбор списка разрешённых каналов |
| `parser.ts` | разбор сообщения-отчёта, без зависимостей от Vencord |
| `ranks.ts` | таблица рангов СМП и проверка |
| `template.ts` | шаблон аудита и подстановка |
| `samples/` | реальные отчёты и эталонные аудиты |
| `test/` | тесты на Node's test runner |
| `scripts/deploy-to-windows.sh` | сборка и доставка в Windows-установку Vencord |
| `LICENSE` | GPL-3.0-or-later, как у Vencord |

## Решения

- **Интерфейс плагина на английском**, потому что пользователь сидит на английском
  клиенте Discord и русский пункт меню выбивался из списка. По-русски остаются
  строки, уходящие в игру: шаблон аудита и названия полей отчёта в сообщениях об
  ошибках. Комментарии в коде и документация — тоже по-русски.
- **Иконка пункта меню задаётся через `leadingAccessory`.** Одного свойства `icon`
  текущему Discord мало — оно легаси, иконка просто не рисуется. Пример правильной
  разметки — `src/plugins/translate/index.tsx` в Vencord.

- **Плагин живёт в отдельном репозитории, а не в форке Vencord.** В форке он
  попал бы под `.gitignore` (`src/userplugins` там игнорируется), либо пришлось
  бы класть его в `src/plugins` и ребейзить поверх ~44 чужих коммитов в месяц.
  Типизация от форка не выигрывает: клон внутри `src/userplugins` и так попадает
  под `include: ["src/**/*"]` и `paths` из tsconfig Vencord. В upstream плагин
  не пойдёт — он завязан на конкретный сервер и бота.

- Проверяющий по умолчанию: `<@178560714821206016>`, «Бронислав Небесный», статик `597`.
  Подтверждено пользователем; вынесено в настройки, а не зашито.
- Пункт меню **ограничен каналом отчётов** `1538690946156462094` (настройка
  `channelIds`, пустое значение снимает ограничение).
- Другие виды аудита (приём, увольнение, понижение, выговор) **не нужны** — только
  повышение.
- Если в `content` нет упоминания повышаемого — аудит не собирается, показывается
  тост с ошибкой. Разбор по одному лишь имени из embed'а ненадёжен: Discord ID
  взять неоткуда.

## Терминология

- **Кадровый аудит** — служебная запись о кадровом изменении (повышение/понижение/
  приём/увольнение), публикуется отдельным сообщением.
- **Средний состав** — категория должностей фракции, отчёты которых проверяет
  пользователь.
- **Статик** — игровой ID персонажа, часто используется в кадровых записях.
