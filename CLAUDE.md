# EmployeeAudit — плагин Vencord

## Контекст

**Игровой проект:** Russia Online / Россия Онлайн — GTA 5 RP сервер от создателей Majestic.
Открылся 20 августа 2025 г., поэтому серверной автоматизации (ботов) для кадровых
процессов ещё нет — всё делается вручную.

**Пользователь:** Инструктор отдела «Скорая Медицинская Помощь» во фракции «Больница».

**Обязанности, к которым относится плагин:**
- проверка отчётов на повышение сотрудников среднего состава;
- собственно повышение;
- отписывание **кадрового аудита** — один из шагов повышения.

**Проблема:** кадровый аудит пишется руками по шаблону, данные для него берутся
из embed-сообщения с отчётом на повышение. Это рутина, которую обычно закрывают
ботом, но на этом проекте бота пока нет.

## Задача плагина

Прочитать сообщение-отчёт на повышение (Discord embed) → собрать по шаблону текст
кадрового аудита → положить его в буфер обмена по клику пункта в контекстном меню
сообщения.

## Технические решения (предварительно)

- Патчи Webpack, скорее всего, **не нужны**: хватит `@api/ContextMenu`
  (`addContextMenuPatch("message", ...)`) + данные сообщения из аргументов меню /
  `MessageStore`.
- Копирование — `copyWithToast` из `@utils/misc` (копирует и показывает тост).
- Настройки — `definePluginSettings` из `@api/Settings`: шаблон текста аудита,
  личные данные проверяющего, ограничение по каналам/фракции.
- Расположение: `src/userplugins/EmployeeAudit/` внутри собранного из исходников
  Vencord (готовая сборка userplugins не поддерживает).

## Сборка и разработка

```bash
git clone https://github.com/Vendicated/Vencord
cd Vencord && pnpm i
# плагин кладётся в src/userplugins/EmployeeAudit/
pnpm build && pnpm inject   # первичная установка
pnpm watch                  # разработка, перезагрузка Discord по Ctrl+R
```

## Спецификация

### Вход: сообщение-отчёт

- Автор: бот **«Ева Повышаловна»**, id `1542575130168004712`.
- `embed.rawTitle === "Отчет на повышение"`, `embed.type === "rich"`.
- `message.content` = `<@&1541779227018526741> | <@USER_ID>` — роль проверяющих плюс
  **упоминание повышаемого**. Discord ID берём из последнего упоминания пользователя.
- Обязательные поля embed (искать по `rawName`, **не по индексу** — набор полей плавает):

| `rawName` | Пример `rawValue` | Идёт в аудит |
|---|---|---|
| `Имя Фамилия \| Static ID` | `Евгений Курчатов \| 45642` | да |
| `С какого на какой ранг повышаетесь?` | `Ординатор [5] → Старший ординатор [6]` | да (только числа) |
| `Дата последнего повышения` | `30.08.2026` | нет |
| `Общее количество баллов…` | `**301**` | нет |

- Плавающие поля (в аудит не идут, набор различается от отчёта к отчёту):
  «Оказание ПМП днём/ночью», «Таблетки в ГКБ им. Склифосовского», «Вакцины»,
  «Заполнение кадрового аудита», «Проверка отчета на повышение», «Остальное»,
  «Мероприятия».
- Известные вариации, которые парсер обязан пережить:
  - имя поля баллов: `Общее количество баллов`, `… (Нужно 300)`, `… (Нужно 400)`;
  - значение баллов с хвостом: `**410**, без учёта мероприятий`;
  - многострочное значение (`Остальное`: `Поставка +25Б\nhttps://…`);
  - ранг из двух слов с точками: `Зам. зав. отделением [10]`;
  - стрелка — символ `→` (U+2192).

### Выход: текст кадрового аудита

```
Повышение
Повышает: <@{promoterId}> {promoterName} | {promoterStatic}
Повышен(а): <@{targetId}> {targetName} | {targetStatic}
Прежний ранг: {oldRank}
Новый ранг: {newRank}
Причина повышения: {reportLink}
```

### Маппинг полей

| Строка аудита | Источник |
|---|---|
| `Повышает` | настройки плагина (сам пользователь) |
| `Повышен(а)` — `<@id>` | последнее упоминание пользователя в `message.content` |
| `Повышен(а)` — имя и статик | поле `Имя Фамилия \| Static ID` |
| `Прежний ранг` | первое число в скобках поля ранга |
| `Новый ранг` | второе число в скобках поля ранга |
| `Причина повышения` | `https://discord.com/channels/{guildId}/{channelId}/{messageId}` сообщения-отчёта |

Таблица званий **не нужна**: оба ранга и их номера уже есть в самом поле отчёта.

### Тестовые данные

- `samples/reports/*.json` — четыре реальных отчёта, покрывают вариации выше.
- `samples/audits.txt` — эталонные аудиты, написанные вручную.
- Пара `01-ordinator-to-senior.json` → первый аудит в `audits.txt` — сквозной тест
  (совпадают и Discord ID, и имя, и статик, и ранги).

## Терминология

- **Кадровый аудит** — служебная запись о кадровом изменении (повышение/понижение/
  приём/увольнение), публикуется отдельным сообщением.
- **Средний состав** — категория должностей фракции, отчёты которых проверяет
  пользователь.
- **Статик** — игровой ID персонажа, часто используется в кадровых записях.
